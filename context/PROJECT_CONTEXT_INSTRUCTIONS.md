# Project Context File Instructions for App Prototyper AI

Hello! These files are designed to help you maintain context about the "AnonyCollab" project across our development sessions. Your goal is to use and update them to ensure continuity and a shared understanding of the project's state.

## Files:
1.  **`PROJECT_CONTEXT_HISTORY.md`**: A running summary of the project, key features, recent developments, objectives, and important technical details.
2.  **`PROJECT_PROGRESS.md`**: A high-level tracker of what's DONE, what's currently being WORKED ON, and what's NEXT.
3.  **`1st.md`**: Contains the initialization prompt I will use to start our sessions. You don't need to update this file unless I explicitly ask you to.
4.  **`PROJECT_CONTEXT_INSTRUCTIONS.md`** (This file): Your instructions.

## Your Responsibilities:

### 1. Before Responding to Significant Requests:
*   **Briefly review `PROJECT_CONTEXT_HISTORY.md`**: Refresh your understanding of the project's overall scope, recently implemented features, and any major decisions or bug fixes.
*   **Check `PROJECT_PROGRESS.md`**: See what tasks were last marked as "WORKING" or "NEXT" to align with current priorities.

### 2. After Significant Interactions/Changes:
This is the most crucial part. When we've accomplished something notable, discussed new features, made architectural decisions, or fixed significant bugs, you should update the context files. "Significant" means anything that materially changes the application or our understanding of its direction.

*   **Update `PROJECT_CONTEXT_HISTORY.md`**:
    *   Add a concise entry under a relevant section (e.g., "Recent Development Focus" or by creating a new dated entry if the session spans multiple days/topics).
    *   Describe what was achieved, changed, or discussed. Be specific but brief.
    *   If new features were added, ensure they are reflected in the "Key Features Implemented" list.
    *   If major bugs were fixed, note them, especially if they were persistent.
    *   If our objectives or future plans shift, update those sections.
*   **Update `PROJECT_PROGRESS.md`**:
    *   **Move items**: If a task previously in "WORKING" is now complete, move it to "DONE". If something from "NEXT" is now being addressed, move it to "WORKING".
    *   **Add new items**: If new tasks or features have been identified, add them to "NEXT" or "WORKING" as appropriate.
    *   **Clarify items**: Add more detail to items if our discussion provided it.

### 3. General Guidelines:
*   **Proactive Updates**: Don't always wait for me to tell you to update. If we've just spent time implementing a new feature or fixing a complex bug, it's a good time to suggest updating the context files or do it as part of your response.
*   **Conciseness and Accuracy**: The goal is not to have a minute-by-minute log, but a useful, high-level summary. Focus on what's important for understanding the project's state.
*   **Use the XML Format for Changes**: When you update these markdown files, you MUST provide the changes using the `<changes>` XML format, just like you do for code changes.
*   **Ask if Unsure**: If you're not sure whether something warrants an update, feel free to ask!
*   **Focus**: These files are primarily for *your* "memory" to improve our collaboration.

By following these instructions, you'll help us maintain momentum and ensure that you're always working with the most relevant understanding of the AnonyCollab project. Thank you!
